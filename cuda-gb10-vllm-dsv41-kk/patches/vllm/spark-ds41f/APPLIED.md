# spark-ds41f patches carried on the vLLM fork 1286ae9c

Twenty-one patch files from `christopherowen/spark-ds41f` at `a2a3abae7b395f98ef64dcc77beef1584d756cd6`, unmodified
(patch headers, authorship and commit messages kept; sha256 below). spark-ds41f is Apache-2.0 since `ad4605b9`
("License the repository under Apache 2.0", PR #355); its license text is `LICENSE.spark-ds41f-Apache-2.0` at the top
of this image directory, and NOTICE attributes it. spark-ds41f's README states that each of its patch series changes
its upstream's code under that project's license, here vLLM's Apache-2.0.

`build/apply_carried_patches.sh` applies them in the order of `series` (not filename order: the series is a stack, and
for example 0001 and 0002 both change `engram.py`), each with `git apply --check` then `git apply`, after the four
patches in `patches/vllm/`, in both places the Dockerfile applies the vLLM patches (the compile stage and the image's
`/src/vllm`). `build/pins_gate.py` reads this table exactly as it reads `patches/vllm/APPLIED.md`: sha256, the
checkout differs from the pin by exactly the carried patches in that order (reversing them restores the pin), every
patched `vllm/` file is installed byte-identical, and each marker appears in an installed patched file. Keep one row
per line and do not put a `|` inside a cell. Each file is also listed in `patches/MD5SUMS.txt` as vendored material.

The order is the one the DSv4.1 Lane A lab layers applied them in on the serving image: Lane A b1 (0024, 0178), then
b2 (13 patches), then b3 (6 patches, sequence-parallel prefill). Strict-apply check: on 1286ae9c plus `patches/vllm/`
0001-0004, all 21 apply with `git apply` in this order, with no fuzz (every context line matches). Eleven of them
(0002, 0007, 0010, 0041, 0042, 0144, 0014-0017, 0025) land 1 to 110 lines away from where their hunk headers say,
because spark-ds41f cut them on its own base and earlier patches in the stack shift lines; `git apply` accepts a
shifted hunk only where its full context matches. Which patches are always on and which are behind a switch is in the
Form column and in the image README ("Carried from spark-ds41f").

Two source paths are worth knowing: 0178 is not under spark-ds41f's `patches/`, it lives only in
`experiments/2026-10-17-r6u/vllm/`; and 0024 is the `patches/vllm/` copy, while spark-ds41f's current series points at
`experiments/2026-10-08-lil-rebase/vllm/0024-...`, which differs only in the `From` commit hash and the abbreviated
`index` hashes (the hunks are identical).
